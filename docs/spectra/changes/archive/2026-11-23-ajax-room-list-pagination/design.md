## Context

`RoomListView` 現在依 `q` 篩選目前登入使用者建立的房間，並把完整 QuerySet 交給 `room_list.html` 伺服器端渲染。模板同時負責顯示房間卡片、空結果與 `rooms|length`；目前沒有分頁、資料端點或前端資料狀態。`Room.Meta.ordering` 已定義為 `-created_at`，可作為穩定的預設排列。

此變更跨越 Django view／URL、模板、瀏覽器 JavaScript 與測試，且要建立後續動態列表可沿用的互動模式，因此需要先固定資料與狀態契約。既有 `apps/majon/tests.py` 尚無測試，實作必須補上可驗證的端點測試。

## Goals / Non-Goals

**Goals:**

- 讓登入使用者不重新載入整頁即可搜尋、換頁並查看自己的房間。
- 建立可測試的 JSON 分頁資料契約與一致的列表畫面狀態。
- 將「動態資料列表使用 AJAX」定為未來列表功能的專案規範。

**Non-Goals:**

- 不改變房間建立、房間詳細頁、資料模型或排序規則。
- 不加入多欄排序、篩選器、無限捲動、快取或共用前端框架。
- 不為未啟用 JavaScript 的瀏覽器保留伺服器端完整列表的替代流程。

## Decisions

### JSON 分頁端點與頁面殼層分離

房間頁 `GET /majon/rooms/` 僅提供搜尋、列表容器與分頁控制所需的 HTML；新增同一資源的資料端點 `GET /majon/rooms/data/`，由瀏覽器以 `fetch` 請求。資料端點接受可選的 `q` 與 `page` 查詢參數，僅查詢 `owner=request.user` 的房間，並套用既有建立時間倒序。

JSON 成功回應固定為：

```json
{
  "items": [
    {
      "id": 12,
      "name": "週五牌局",
      "code": "FRI-01",
      "owner_display_name": "小明",
      "detail_url": "/majon/rooms/12/"
    }
  ],
  "page": 1,
  "page_size": 10,
  "total_count": 23,
  "total_pages": 3,
  "has_previous": false,
  "has_next": true
}
```

`owner_display_name` 使用 profile 的 `display_name`；未設定時使用 username。缺少、非整數或小於 1 的 `page` 一律視為第 1 頁；超過最後一頁的頁碼回傳最後一頁。這使網址列或手動修改查詢參數不會造成前端無法渲染。

替代方案是由同一端點依 `Accept` 標頭回傳 HTML 或 JSON；不採用，因為雙重回應格式會使測試、錯誤處理與日後列表慣例變得不明確。

### AJAX 搜尋與分頁的請求協調

前端在初次載入後立即取得第 1 頁。使用者輸入搜尋字詞後等待 300 毫秒再請求第 1 頁；點擊上一頁、下一頁或頁碼時，以目前搜尋字詞請求指定頁。新請求開始時以 `AbortController` 取消進行中的請求，並以最近一次請求為唯一可更新畫面的結果，避免較早的回應覆蓋較新的搜尋或頁碼。

每次成功回應以 API 的 `total_count` 顯示總房間數，並依回傳的頁碼資訊產生分頁控制。搜尋關鍵字使用目前既有的房間名稱不分大小寫包含比對。

替代方案是只用按下搜尋按鈕觸發請求；不採用，因為輸入等待能在保有鍵盤操作的同時避免每一個字元都送出請求。表單提交仍攔截為 AJAX 請求，作為等待期間以外的立即搜尋操作。

### 載入、空結果與錯誤狀態

初次資料請求期間，列表容器使用骨架卡片，並以 `aria-busy="true"` 和可讀取的狀態文字宣告「正在載入房間」。後續搜尋或換頁期間保留上一次成功清單、標示更新中，並停用會重複觸發同一操作的分頁控制。

回應成功但 `items` 為空時顯示空結果說明；它不是錯誤。網路錯誤、逾時、非 2xx 回應或無法解析的資料回應時，若已有成功清單則保留該清單並在上方顯示錯誤與「重新載入」；若尚無成功清單，則在列表區顯示錯誤與重試。取消的舊請求不顯示錯誤。狀態訊息使用可被螢幕閱讀器宣告的區域。

替代方案是每個請求清空清單並只顯示 spinner；不採用，因為短暫失敗和連續操作會造成內容跳動，並讓使用者失去最後一次成功資料。

### 動態資料列表的共通規範

「動態資料列表」是會因資料庫內容、登入者身分或使用者查詢而改變的一組項目，例如房間、對局或使用者紀錄。這類列表未來一律以受權限保護的 AJAX 資料端點、後端分頁、可區分載入／空結果／失敗的前端狀態實作。靜態導覽、固定選項與不依資料來源變動的內容不屬於此規範。

此變更以規格保存該規範，而非現在建立通用 JavaScript 抽象；新列表可先遵守相同契約與狀態，只有重複需求出現時才抽取共用元件。

## Implementation Contract

**Behavior**

- 已登入使用者開啟房間列表後，頁面 SHALL 以 AJAX 顯示其房間第一頁；搜尋與分頁 SHALL 不重新載入整個文件。
- 一頁包含 10 筆資料；搜尋與分頁結果 SHALL 僅包含目前登入使用者擁有的房間。
- 未登入者請求資料端點 SHALL 收到 JSON 401 回應，而不是登入 HTML 頁面。

**Interface / data shape**

- `GET /majon/rooms/data/?q=<string>&page=<positive integer>` SHALL 回傳 Decisions 所列的成功 JSON 結構；每個 item SHALL 有安全可用於畫面連結的詳細頁 URL。
- API 端點的 `q` 空白前後 SHALL 忽略，空字串代表不篩選；`page` 的無效值依「JSON 分頁端點與頁面殼層分離」決策正規化。
- API 的非預期伺服器失敗 SHALL 使用 JSON 錯誤回應，供前端辨識為失敗；前端 SHALL 不把 HTML 錯誤頁當成列表資料。

**Failure modes**

- 瀏覽器取消被取代的請求時 SHALL 靜默處理，不顯示錯誤。
- 初次請求失敗與後續請求失敗 SHALL 顯示重試操作；後者 SHALL 保留最後一次成功的列表。

**Acceptance criteria**

- Django 測試覆蓋未登入、擁有者隔離、名稱搜尋、每頁 10 筆、總筆數與邊界頁碼。
- 瀏覽器手動驗證初次載入、搜尋、換頁、無結果、請求失敗後重試，以及快速輸入搜尋時不顯示過期資料。
- 新列表實作依 `ajax-list-data` 規格採用相同的 AJAX、分頁與狀態分類。

**Scope boundaries**

- 範圍包含房間列表頁、其資料端點與共通列表規格。
- 範圍不包含其他現有頁面的改造；它們在各自功能變更時才套用共通規範。

## Risks / Trade-offs

- [JavaScript 請求失敗使初次列表不可用] → 顯示可理解的錯誤與重試，並在後續失敗時保留已成功資料。
- [快速搜尋的非同步回應順序錯置] → 取消前一請求並只接受最新請求的結果。
- [前端顯示的總數與當頁項目數混淆] → 使用 API 的 `total_count` 顯示總數，不以當頁 items 長度替代。
- [未登入 API 請求被導向 HTML 登入頁] → 對資料端點明確回傳 JSON 401，並納入測試。

## Migration Plan

1. 先加入資料端點、端點測試與前端 AJAX 行為，再把房間列表模板改為畫面殼層。
2. 在本機以已登入與未登入身分驗證 API，並手動檢查各列表狀態。
3. 若需要回復，可移除資料端點與列表 JavaScript，並還原為既有伺服器端完整列表模板；資料模型不會變更，因此不需要資料遷移。
